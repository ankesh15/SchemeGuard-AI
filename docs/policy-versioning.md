# Monitoring and policy versions

Document bytes and eligibility rules have distinct versions. Changed SHA-256 bytes create a preserved DocumentVersion through the existing secure ingestion service. A document change alone never activates eligibility rules. Exact ETag/Last-Modified hints can avoid fetching an unchanged body; unconditional weekly checksum checks prevent treating headers as permanent truth. Redirects remain rejected: separately approve the final official URL. TLS pinning, public-address checks, byte/page limits and parser subprocess limits are reused.

The monitor first reuses text-only parsing. Identical normalized source text can skip a paid AI extraction and is labeled FORMATTING/NO_POLICY_CHANGE; this is not a proof about visual tables, and the source remains potentially outdated for human inspection. Changed text starts the existing durable LangGraph workflow and pauses at its human review. Missing Gemini credentials or unrepresentable policy concepts fail safely while the last approved policy remains available.

`policy_diff.py` compares typed expression leaves using stable identifiers, logical context, field, exclusions, operators and normalized values. Threshold increases/decreases, categorical/state/education changes, additions/removals, logical changes and uncertainty are recorded with old/new evidence. Missing candidate conditions are inconclusive until completeness has actually been reviewed. Explicit self-contained application-deadline and required-document labels can be compared as non-executable source facts; ambiguous/missing mentions remain inconclusive. No deadline operator or unsupported engine field is invented.

Comparison snapshots are append-only per saved review revision. The original proposal stays immutable. A human sees old/new rules and evidence, document versions, dates and classification in `/admin/policy-changes`. Clarification requires a new saved Phase 4 revision. Approve/reject reuses its exact-digest, complete-policy and page-inspection contract. Direct Phase 4 decisions apply the same linked-change safeguards. Only a matching human-approved RuleSet can mark a change APPROVED; that transition is part of the publication transaction.

Overlapping approved rule versions require an explicit RulePublication replacement relationship. The repository raises 409 instead of silently selecting unrelated overlapping versions. A malformed candidate approved configuration fails closed with 503. Effective date gaps produce no approved rule and UNKNOWN. Historic rules/evidence are immutable. Public synthetic assessment requests may include `assessed_on`; private saved assessments in Phase 6 additionally pin the exact evaluated rule/version and minimal encrypted input snapshot.

Dates are never inferred from download time. A missing effective date blocks publication. A reviewer activation date is labeled as administrative activation, not a government-announced date. Differing applicability scopes require reconciliation during review; this MVP does not infer geographic policy precedence from natural language. Only approved changes with published versions appear at `/api/v1/policy-updates`.
