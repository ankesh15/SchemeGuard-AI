# Database design and migrations

PostgreSQL 16 is used through SQLAlchemy 2.x and asyncpg. UUIDs identify all domain rows. All stored timestamps are timezone-aware; verification and publication dates use SQL dates. UUIDs are generated by the application, so no extension is needed. pgvector is deferred until vector search is requested.

## Tables

| Table | Purpose | Important fields and constraints |
| --- | --- | --- |
| `schemes` | Discovery metadata | UUID PK; unique variant slug; name, description, ministry, department, category, explicit geography, verification date, status; created/updated timestamps |
| `scheme_sources` | Official evidence for scheme metadata | UUID PK; scheme FK with delete restriction; HTTPS URL, title, publisher, supported fields, verification notes/date; one primary source per scheme through a partial unique index; unique scheme/URL pair |
| `document_versions` | Immutable future document history | UUID PK; source FK; positive version number/byte count; lowercase SHA-256; media type/storage key; retrieved/published dates; optional same-source supersession |

Relationships are one scheme to many sources, and one source to many document versions. The stable scheme ID can later anchor eligibility rule versions. Future rule versions should reference immutable document-version IDs and reviewed evidence, rather than a mutable current URL. Rule tables and approval workflows do not exist in Phase 1.

The primary official URL is derived from the primary source record instead of being duplicated on `schemes`. List queries eagerly load source records; details expose the evidence. Source URLs are evidence references, not immutable document snapshots. `document_versions` starts empty until actual document bytes can be captured and hashed in a later phase.

## Unknowns, history, and indexes

`status` is constrained to `listed`, `inactive`, or `unknown`. A `listed` value records official directory presence on `verified_on`; it does not encode an application window. Optional facts remain SQL NULL when unverified.

Geography has a database check constraint:

- `unknown` requires `applicable_states IS NULL`.
- `national` requires an empty, non-null state array and explicit supporting evidence at the application boundary.
- `states` requires a non-empty, non-null state array. Seed validation restricts values to known Indian state/UT names.

A GIN index supports state-array containment; B-tree indexes support category filtering, stable name/UUID ordering, and foreign-key lookups. `%term%` substring search is parameterized and escapes wildcard characters but is not indexed at this small scale. A later search phase may introduce trigram/full-text indexes after measuring requirements.

Document versions are unique by `(source_id, version_number)` and `(source_id, content_sha256)`. A composite foreign key prevents supersession across different sources; self-supersession is prohibited. Database triggers reject UPDATE, DELETE, and TRUNCATE on document versions. Foreign keys prevent deleting schemes or sources that are still referenced. A scheme UPDATE trigger maintains `updated_at` even for direct SQL changes. Database owners can bypass protections or run destructive DDL; these invariants assume normal application/database use and are not tamper-proof archival storage.

## Migration operations

Initial revision: `0001_initial_metadata` (three tables, indexes, foreign/check/unique constraints, and history/timestamp triggers).

```bash
docker compose exec api alembic upgrade head
docker compose exec api alembic current
docker compose exec api alembic check
docker compose exec api python -m app.seed
```

Automatic startup upgrades are idempotent. Seeding acquires a PostgreSQL transaction advisory lock, validates the complete manifest, inserts only absent slugs and their sources, and commits atomically. Existing records are preserved without rewriting dates or content. Future reviewed metadata refreshes need an explicit change path; rerunning this seed is not a policy update mechanism.

Every schema change must add an Alembic migration. Do not edit an applied revision. The downgrade to `base` removes all three tables and is destructive; only the automated round-trip test uses it, in a disposable test database. Regular operation never downgrades or clears application records.

## Persistence and tests

The `schemeguard-ai_postgres_data` named volume stores `/var/lib/postgresql/data`. `docker compose down` and service recreation preserve it. The verification script compares all rows before and after recreating both services. Deleting the volume deletes the database. No backup is provided by a Docker volume alone.

`python -m tests.run` creates a fresh randomly named PostgreSQL database using the development role, applies actual migrations, and runs the integration suite. Tests use transaction rollback for isolation and a second generated database for migration round trips. Cleanup only drops generated test databases. Missing PostgreSQL test configuration is an error, not a skipped suite.
