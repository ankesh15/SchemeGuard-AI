# Security audit and deployment assumptions

Phase 7 reviewed authentication, private ownership, ingestion/fetching, model output mapping, LangGraph publication, RAG scope, monitoring/reassessment, Docker secrets and dependencies. Confirmed fixes: a password-change/in-flight-login session race now rechecks the verified hash under the account lock; all HTTP bodies are bounded before JSON decoding; unbounded private pagination is capped; host headers require an explicit allowlist; third-party log messages cannot echo URL/API secrets; exception events retain safe request correlation; deployment SQL drivers share correct TLS DSN conversion; production uses a runtime DML role rather than the schema owner; browser traffic uses fixed same-origin proxies; and production HTML has per-request nonces with strict-dynamic CSP. Authentication controls remain disabled until hydrated. Browser tests wait for the actual new-page form before entering synthetic credentials.

Existing protections remain: Argon2id; hashed opaque revocable sessions; Secure production/HttpOnly/Strict cookies; CSRF and exact-origin checks; forced citizen registration role; every private query owner-scoped; administrator authorization on document/review/monitoring actions; rate limits; finite typed ASTs without eval/exec; located page-level evidence and a human publication interrupt; TLS/IP-pinned official fetches rejecting unsafe destinations/redirects; PDF content/size/page/CPU/memory/time bounds; private content-addressed originals; encrypted owner/purpose-bound applicant payloads; and immutable document/rule/report history.

The public proxy is allowlisted and never forwards cookies or arbitrary upstream hosts. Private proxies forward only required authentication headers/cookie; no database, Redis, Gemini or encryption secret reaches a browser bundle. CSP forbids arbitrary script execution, frames, objects and external connections. Styles retain unsafe-inline for framework/layout compatibility; scripts do not. Nonces require dynamic HTML (no shared cached HTML/ISR). Next.js emits nonce attributes on its framework scripts; the production TLS smoke check verifies them. The proxy does not perform authorization; backend checks and protected layouts remain authoritative.

Production runtime roles cannot create schemas/databases/roles or alter the schema. Grants reject privileged/owner-member roles, preserve existing passwords and exclude audit updates/deletes. Migration ownership remains an explicit release-only operation. PostgreSQL and Redis are not host-published; Redis is a trusted private broker with ID-only messages, not an authorization boundary or result store. Managed Redis should use rediss/TLS and restricted credentials/network policy. Host-local ports require a real HTTPS edge/load balancer. The optional local TLS harness is exclusively a verification tool, not a production server.

S3 uses the operator-configured bucket/prefix and AWS SDK credential chain, private conditional content-addressed writes, server-side AES256 encryption, bounded reads and SHA-256 verification. Grant GetObject/PutObject only for the document prefix, enable bucket versioning, block all public access, require TLS and configure independent backups/retention. Existing originals must be copied/verified before switching storage. Live bucket policy, IAM, encryption-at-rest and cloud connectivity require operator verification; no cloud resource was created in this phase.

Dependency reports use the actual pinned runtime lock and npm advisory service. No advisory ignore list or invented clean result is used. Results/dates are recorded in testing.md. This does not constitute a penetration test, OS-image vulnerability scan, legal/privacy compliance certification or proof that no unknown vulnerabilities exist. Keep base images, PostgreSQL, Redis, PyMuPDF, SDKs and advisory scans current.

Remaining deployment responsibilities: real certificates/DNS, managed-network controls, secret-manager/key rotation and backup custody, approved government-policy reconciliation, MFA/recovery delivery, retention policies, trusted-edge IP/rate-limit capacity and high-volume load testing. Parser resource isolation is not a separate kernel sandbox: keep native libraries patched and consider dedicated parsing isolation for hostile internet-scale uploads. A privileged database owner/storage operator can bypass application protections. Public AI quotas, bounded retries and per-process slots reduce cost but are not a substitute for edge abuse protection. Independent human evaluation and real Gemini accuracy are unverified.
